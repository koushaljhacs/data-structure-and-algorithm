=================================================================================
                    1. FUNDAMENTAL CONCEPTS & CORE IDEA
=================================================================================

1.1 WHAT IS SELECTION SORT?
────────────────────────────
Selection Sort is an IN-PLACE, COMPARISON-BASED sorting algorithm that divides the
input array into two logical segments:

┌─────────────────────────────────────────────────────────────┐
│   SORTED SUBARRAY      │        UNSORTED SUBARRAY           │
│   (Left side)          │        (Right side)                │
│   Initially empty      │        Initially entire array      │
│   Grows left to right  │        Shrinks right to left       │
└─────────────────────────────────────────────────────────────┘

1.2 CORE PRINCIPLE:
───────────────────
"Find the minimum element in the unsorted subarray and swap it with the first
 element of the unsorted subarray."

In each iteration i (0 to n-2):
1. Find minimum element in arr[i...n-1]
2. Swap it with arr[i]
3. Increment the sorted subarray boundary

1.3 VISUAL ANALOGY:
───────────────────
Imagine you have a deck of cards face up on a table. To sort them in ascending order:
1. Scan all cards to find the smallest card
2. Pick it up and place it as the first card in your sorted pile
3. Repeat with remaining cards until no cards remain on table

2.1 STEP-BY-STEP EXECUTION:
────────────────────────────
Array: [64, 25, 12, 22, 11]

PASS 1:
───────
• Entire array is unsorted: [64, 25, 12, 22, 11]
• Find minimum: 11 at index 4
• Swap with arr[0]: [11, 25, 12, 22, 64]
• Sorted: [11] | Unsorted: [25, 12, 22, 64]

PASS 2:
───────
• Unsorted: [25, 12, 22, 64]
• Find minimum: 12 at index 2
• Swap with arr[1]: [11, 12, 25, 22, 64]
• Sorted: [11, 12] | Unsorted: [25, 22, 64]

PASS 3:
───────
• Unsorted: [25, 22, 64]
• Find minimum: 22 at index 3
• Swap with arr[2]: [11, 12, 22, 25, 64]
• Sorted: [11, 12, 22] | Unsorted: [25, 64]

PASS 4:
───────
• Unsorted: [25, 64]
• Find minimum: 25 at index 3
• Swap with arr[3]: [11, 12, 22, 25, 64]
• Sorted: [11, 12, 22, 25] | Unsorted: [64]

RESULT: [11, 12, 22, 25, 64]

2.2 PSEUDOCODE:
───────────────
procedure selectionSort(A: list of sortable items)
    n = length(A)
    for i = 0 to n-2 do
        minIndex = i
        for j = i+1 to n-1 do
            if A[j] < A[minIndex] then
                minIndex = j
            end if
        end for
        if minIndex ≠ i then
            swap(A[i], A[minIndex])
        end if
    end for
end procedure

2.3 INVARIANTS:
───────────────
1. After i iterations, the first i elements are in sorted order.
2. The element at position i is the smallest among A[i...n-1].
3. The unsorted portion A[i+1...n-1] contains elements ≥ A[i].

               3. MATHEMATICAL ANALYSIS & COMPLEXITY

3.1 TIME COMPLEXITY ANALYSIS:
─────────────────────────────

3.1.1 COMPARISONS COUNT:
╔═══════════════════════════════════════════════════════════════════╗
║                        COMPARISONS ANALYSIS                       ║
╠═══════════════╦═══════════════════════════════════════════════════╣
║ Pass Number   ║            Comparisons in this Pass               ║
╠═══════════════╬═══════════════════════════════════════════════════╣
║ Pass 1        ║ Compare A[1]...A[n-1] with A[0]: (n-1) comparisons║
║ Pass 2        ║ Compare A[2]...A[n-1] with A[1]: (n-2) comparisons║
║ Pass 3        ║ Compare A[3]...A[n-1] with A[2]: (n-3) comparisons║
║ ...           ║ ...                                               ║
║ Pass i        ║ Compare A[i+1]...A[n-1] with A[i]: (n-i-1) comps  ║
║ ...           ║ ...                                               ║
║ Pass n-1      ║ Compare A[n-1] with A[n-2]: 1 comparison          ║
╚═══════════════╩═══════════════════════════════════════════════════╝

TOTAL COMPARISONS = (n-1) + (n-2) + ... + 2 + 1
                  = Σ(k=1 to n-1) k
                  = n(n-1)/2

Thus, Number of comparisons = n(n-1)/2 = O(n²)

3.1.2 SWAPS COUNT:
╔══════════════════════════════════════════════════════════════════╗
║                          SWAPS ANALYSIS                          ║
╠═══════════════════════╦══════════════════════════════════════════╣
║ Best Case             ║ 0 swaps (array already sorted)           ║
╠═══════════════════════╬══════════════════════════════════════════╣
║ Worst Case            ║ n-1 swaps                                ║
╠═══════════════════════╬══════════════════════════════════════════╣
║ Average Case          ║ ≈ n/2 swaps                              ║
╚═══════════════════════╩══════════════════════════════════════════╝

Each swap requires 3 operations (using temporary variable):
swap(a, b):
    temp = a
    a = b
    b = temp

Total swap operations = 3 × number_of_swaps = O(n)

╔═══════════════════════╦══════════════════════════════════════════╗
║        Case           ║           Time Complexity                ║
╠═══════════════════════╬══════════════════════════════════════════╣
║ Best Case             ║ Θ(n²) comparisons + Θ(0) swaps           ║
╠═══════════════════════╬══════════════════════════════════════════╣
║ Average Case          ║ Θ(n²) comparisons + Θ(n) swaps           ║
╠═══════════════════════╬══════════════════════════════════════════╣
║ Worst Case            ║ Θ(n²) comparisons + Θ(n) swaps           ║
╚═══════════════════════╩══════════════════════════════════════════╝

3.2 SPACE COMPLEXITY:
─────────────────────
• In-place algorithm: O(1) auxiliary space
• Only requires a few temporary variables:
  - i, j, minIndex: O(1)
  - temp for swapping: O(1)
• No recursion stack (iterative)
• No additional arrays needed

Space Complexity = O(1) [Excellent for memory-constrained environments]

3.3 MATHEMATICAL PROOF OF COMPARISONS:
──────────────────────────────────────
Theorem: Selection Sort performs exactly n(n-1)/2 comparisons for any input of size n.

Proof by Mathematical Induction:
────────────────────────────────
Base Case (n=1): 0 comparisons = 1(0)/2 = 0 ✓
Base Case (n=2): 1 comparison = 2(1)/2 = 1 ✓

Inductive Hypothesis: Assume true for n=k, i.e., C(k) = k(k-1)/2

Inductive Step: For n=k+1:
C(k+1) = C(k) + k   [k comparisons in first pass for array of size k+1]
        = k(k-1)/2 + k
        = (k² - k + 2k)/2
        = (k² + k)/2
        = k(k+1)/2
        = (k+1)k/2 ✓

Thus, proved by induction.

=================================================================================
                   4. STABILITY & ADAPTIVITY ANALYSIS
=================================================================================

4.1 STABILITY ANALYSIS:
───────────────────────
Definition: A sorting algorithm is STABLE if it preserves the relative order
            of equal elements.

Selection Sort is GENERALLY UNSTABLE. Reason: Long-distance swaps.

Example demonstrating instability:
─────────────────────────────────
Array: [(5, red), (3, blue), (5, green), (2, yellow)]
Step 1: Find min = (2, yellow) at index 3
        Swap with index 0: [(2, yellow), (3, blue), (5, green), (5, red)]
        ↑ The two 5's have swapped relative order!

However, Selection Sort CAN BE MADE STABLE by modifying the swap to shift
elements instead:

Stable Selection Sort Pseudo-code:
──────────────────────────────────
for i = 0 to n-2:
    minIndex = i
    for j = i+1 to n-1:
        if arr[j] < arr[minIndex]:
            minIndex = j
    
    # Instead of swap, shift elements right
    key = arr[minIndex]
    for k = minIndex down to i+1:
        arr[k] = arr[k-1]
    arr[i] = key

Trade-off: Stability achieved at cost of O(n²) shifts instead of O(n) swaps.

4.2 ADAPTIVITY ANALYSIS:
────────────────────────
Definition: An algorithm is ADAPTIVE if it takes advantage of existing order
            in the input (performs better on partially sorted data).

Selection Sort is NON-ADAPTIVE. Reason: It always performs the same number
of comparisons regardless of input order.

Proof of Non-adaptivity:
─────────────────────────
For Selection Sort:
• Already sorted array: n(n-1)/2 comparisons
• Reverse sorted array: n(n-1)/2 comparisons  
• Random array: n(n-1)/2 comparisons

All cases have exactly the same comparison count!

5.1 BASIC IMPLEMENTATION (C++):
───────────────────────────────
void selectionSort(int arr[], int n) {
    for (int i = 0; i < n-1; i++) {
        int minIdx = i;
        for (int j = i+1; j < n; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
            }
        }
        if (minIdx != i) {
            // Swap
            int temp = arr[i];
            arr[i] = arr[minIdx];
            arr[minIdx] = temp;
        }
    }
}

5.2 IMPLEMENTATION WITH EARLY EXIT OPTIMIZATION:
────────────────────────────────────────────────
void optimizedSelectionSort(int arr[], int n) {
    for (int i = 0; i < n-1; i++) {
        int minIdx = i;
        bool isSorted = true;  // Check if already sorted
        
        for (int j = i+1; j < n; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
                isSorted = false;
            }
            // Additional check for early exit
            if (j > i+1 && arr[j] < arr[j-1]) {
                isSorted = false;
            }
        }
        
        if (minIdx != i) {
            swap(arr[i], arr[minIdx]);
        }
        
        // Early exit if array is already sorted
        if (isSorted) {
            break;
        }
    }
}

5.3 BIDIRECTIONAL (COCKTAIL) SELECTION SORT:
─────────────────────────────────────────────
void bidirectionalSelectionSort(int arr[], int n) {
    int left = 0, right = n-1;
    
    while (left < right) {
        int minIdx = left, maxIdx = right;
        
        // Find min and max in current range
        for (int i = left; i <= right; i++) {
            if (arr[i] < arr[minIdx]) minIdx = i;
            if (arr[i] > arr[maxIdx]) maxIdx = i;
        }
        
        // Place min at left
        if (minIdx != left) {
            swap(arr[left], arr[minIdx]);
            // If max was at left, it moved to minIdx
            if (maxIdx == left) maxIdx = minIdx;
        }
        
        // Place max at right
        if (maxIdx != right) {
            swap(arr[right], arr[maxIdx]);
        }
        
        left++;
        right--;
    }
}
// Reduces passes by ~50%, but comparisons remain O(n²)

=================================================================================
                    7. OPTIMIZATION TECHNIQUES
=================================================================================

7.1 BIDIRECTIONAL SELECTION SORT:
──────────────────────────────────
• Also called "Double Selection Sort" or "Cocktail Selection Sort"
• Finds both min AND max in each pass
• Places min at beginning, max at end
• Reduces number of passes by ~50%

Complexity Analysis:
• Comparisons per pass: 2 × (n - 2i) comparisons
• Total comparisons: Still O(n²) but with lower constant factor
• Swaps: Up to 2 per pass

7.2 HEAP-ASSISTED SELECTION SORT:
──────────────────────────────────
• Build a min-heap from the array: O(n) time
• Repeatedly extract min: O(log n) per extraction
• Total: O(n log n) - becomes Heap Sort!

This optimization transforms Selection Sort into Heap Sort, which is an
entirely different algorithm with better asymptotic complexity.

7.3 CACHE-OPTIMIZED SELECTION SORT:
────────────────────────────────────
Problem: Selection Sort has poor cache performance due to random access pattern.

Solution: Block Selection Sort
1. Divide array into blocks that fit in cache
2. Find minimum in each block
3. Compare block minima to find global minimum
4. Move global minimum to sorted position

Pseudo-code:
void blockSelectionSort(int arr[], int n, int blockSize) {
    for (int i = 0; i < n-1; i++) {
        int minIdx = i;
        
        // Process in blocks
        for (int blockStart = i+1; blockStart < n; blockStart += blockSize) {
            int blockEnd = min(blockStart + blockSize, n);
            
            // Find min in current block
            for (int j = blockStart; j < blockEnd; j++) {
                if (arr[j] < arr[minIdx]) {
                    minIdx = j;
                }
            }
        }
        
        if (minIdx != i) {
            swap(arr[i], arr[minIdx]);
        }
    }
}

7.4 EARLY TERMINATION OPTIMIZATION:
────────────────────────────────────
void earlyTerminationSelectionSort(int arr[], int n) {
    bool swapped;
    for (int i = 0; i < n-1; i++) {
        swapped = false;
        int minIdx = i;
        
        for (int j = i+1; j < n; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
                swapped = true;
            }
        }
        
        if (minIdx != i) {
            swap(arr[i], arr[minIdx]);
        }
        
        // Early termination if no swap occurred
        if (!swapped) {
            break;
        }
    }
}
Note: This only helps if array becomes sorted before all passes complete.

              8. REAL-WORLD APPLICATIONS & USE CASES
=================================================================================

8.1 WHEN TO USE SELECTION SORT:
───────────────────────────────
1. SMALL DATASETS (n < 50):
   • Overhead of O(n log n) algorithms not justified
   • Code simplicity more important than speed

2. MEMORY WRITE-CONSTRAINED ENVIRONMENTS:
   • Flash memory (limited write cycles)
   • EEPROM programming
   • Embedded systems with NAND flash
   • Selection Sort: O(n) writes vs Bubble Sort: O(n²) writes

3. PREDICTABLE PERFORMANCE NEEDED:
   • Real-time systems where worst-case = average-case
   • Safety-critical systems (certification requirements)
   • Selection Sort: Always O(n²), no surprises

4. TEACHING AND LEARNING:
   • Simple to understand and implement
   • Demonstrates fundamental sorting concepts
   • Good starting point before learning more complex algorithms

5. HYBRID ALGORITHMS:
   • Introsort: Uses Selection Sort for small partitions (n < 16)
   • Some implementations of QuickSort use Selection Sort for small arrays

8.2 WHEN TO AVOID SELECTION SORT:
─────────────────────────────────
1. LARGE DATASETS (n > 1000):
   • O(n²) becomes prohibitively slow
   • Use QuickSort, MergeSort, or HeapSort instead

2. NEARLY SORTED DATA:
   • Selection Sort doesn't take advantage of existing order
   • Insertion Sort would be O(n) for nearly sorted data

3. STABILITY REQUIRED:
   • Default Selection Sort is unstable
   • Use Insertion Sort or Merge Sort for stable sorting

4. LINKED LISTS:
   • Selection Sort inefficient on linked lists
   • Insertion Sort is natural for linked structures

8.3 REAL-WORLD SCENARIOS:
─────────────────────────
1. EMBEDDED SYSTEMS:
   • Sorting sensor readings in microcontrollers
   • Organizing data in IoT devices with limited memory

2. GRAPHICS PROGRAMMING:
   • Sorting small batches of sprites by depth
   • Z-buffer management for small objects

3. DATABASE SYSTEMS:
   • Sorting small result sets
   • Index maintenance for small tables

4. GAME DEVELOPMENT:
   • Sorting game objects by priority
   • Organizing particles in particle systems

         9. ADVANCED INTERVIEW QUESTIONS (FAANG LEVEL)
=================================================================================

9.1 BRAIN TEASERS & DEEP CONCEPTUAL QUESTIONS:
───────────────────────────────────────────────

Q1: "If all elements are identical, which O(n²) sort is best and why?"
A1: INSERTION SORT is optimal for identical elements.
    • Selection Sort: Still performs n(n-1)/2 comparisons
    • Bubble Sort (unoptimized): n(n-1)/2 comparisons
    • Insertion Sort: Only n-1 comparisons (each element inserted immediately)
    Complexity: Insertion → O(n), Selection/Bubble → O(n²)

Q2: "Can Selection Sort be implemented using only Stack operations?"
A2: Yes, but highly inefficient (O(n³)):
    • Use 3 stacks: main, temp, sorted
    • Repeatedly find min by popping/repushing
    • TC: O(n³) comparisons, O(n²) stack ops

Q3: "What's the minimum number of comparisons needed to prove array is sorted?"
A3: For Selection Sort logic: n-1 comparisons.
    Proof: After finding min at position i, if arr[i+1] ≥ arr[i] for all i,
    then array is sorted. But Selection Sort doesn't check this - it always
    does n(n-1)/2 comparisons.

Q4: "How would you modify Selection Sort for external sorting (disk-based)?"
A4: External Selection Sort would be terrible due to O(n²) disk seeks.
    Better approach:
    1. Read chunks that fit in memory
    2. Sort chunks with in-memory algorithm (not Selection Sort)
    3. Merge sorted chunks using k-way merge

Q5: "Selection Sort on quantum computer - what's the complexity?"
A5: Using Grover's search for finding minimum:
    • Finding min in unsorted portion: O(√m) where m = n-i
    • Total: Σ√k for k=n..1 ≈ O(n√n)
    • Still worse than quantum merge sort O(n log n)

9.2 CODING CHALLENGES:
──────────────────────

Q6: "Implement Selection Sort without using if statements"
A6: Use conditional operator or arithmetic tricks:
    void selectionSortNoIf(int arr[], int n) {
        for (int i = 0; i < n-1; i++) {
            int minIdx = i;
            for (int j = i+1; j < n; j++) {
                // Using conditional operator
                minIdx = (arr[j] < arr[minIdx]) ? j : minIdx;
                
                // Or using arithmetic (slower, for demonstration):
                // int less = arr[j] < arr[minIdx];
                // minIdx = less * j + (1-less) * minIdx;
            }
            swap(arr[i], arr[minIdx]);
        }
    }

Q7: "Selection Sort with exactly k swaps - is it possible?"
A7: Selection Sort always does between 0 and n-1 swaps.
    • To achieve exactly k swaps: 
      - First k elements should be out of order
      - Remaining n-k elements should be in correct position
    Example for k=2: [3, 2, 1, 4, 5] → swaps 3↔1 and 2↔1

Q8: "Find the permutation that maximizes Selection Sort swaps"
A8: Reverse sorted array maximizes swaps: n-1 swaps.
    Proof: In reverse order, each element is minimum of remaining unsorted portion.

9.3 PERFORMANCE ANALYSIS QUESTIONS:
────────────────────────────────────

Q9: "How many times is the swap() function called in worst case?"
A9: Exactly n-1 times. Each iteration may perform at most one swap.

Q10: "What's the exact formula for number of assignments?"
A10: Let A = number of assignments (excluding comparisons)
     Minimum: 3×(n-1) + n-1 = 4n-4 (if minIdx updates n-1 times)
     Maximum: 3×(n-1) + Σ(k=1 to n-1) k = 3n-3 + n(n-1)/2

Q11: "Cache miss analysis for Selection Sort"
A11: Selection Sort has terrible cache performance:
     • Each inner loop iteration accesses random memory locations
     • Spatial locality: Poor (non-sequential access)
     • Temporal locality: Poor (each element accessed few times)
     Expected cache misses: O(n²) in worst case

=================================================================================

10.1 EDGE CASE ANALYSIS:
────────────────────────

1. EMPTY ARRAY:
   • n = 0
   • Algorithm should do nothing
   • Need guard clause: if (n <= 1) return;

2. SINGLE ELEMENT ARRAY:
   • Already sorted
   • Outer loop runs 0 times (i < n-1 = 0 < 0 false)
   • No comparisons, no swaps

3. TWO ELEMENT ARRAY:
   • Best case: [1, 2] → 1 comparison, 0 swaps
   • Worst case: [2, 1] → 1 comparison, 1 swap
   • Always 1 comparison: n(n-1)/2 = 2×1/2 = 1

4. ALREADY SORTED ARRAY:
   • Comparisons: n(n-1)/2 (full amount)
   • Swaps: 0
   • minIdx updates: n-1 times (each time finds min at current position)

5. REVERSE SORTED ARRAY:
   • Comparisons: n(n-1)/2
   • Swaps: n-1 (maximum)
   • Example: [5,4,3,2,1] → 4 swaps

6. ALL ELEMENTS IDENTICAL:
   • Comparisons: n(n-1)/2
   • Swaps: 0
   • Important: Even though no swaps, still full comparisons

7. ARRAY WITH NEGATIVE NUMBERS:
   • Works correctly
   • Comparisons use < operator which handles negatives
   • Example: [-5, -1, -10] → sorted: [-10, -5, -1]

8. ARRAY WITH MIXED TYPES (if language allows):
   • Requires comparison operator definition
   • For custom objects, need comparator function

10.2 CORNER CASES FOR OPTIMIZED VERSIONS:
─────────────────────────────────────────

1. BIDIRECTIONAL WITH DUPLICATE MIN/MAX:
   • If min and max are same element
   • Need to handle carefully to avoid double-swap
   • Solution: Check if minIdx == maxIdx after finding min

2. EARLY TERMINATION WITH ALL IDENTICAL:
   • Without optimization: n(n-1)/2 comparisons
   • With early termination: Still n(n-1)/2 (no early exit possible)
   • Reason: swapped flag never set to true

3. STABLE VERSION WITH SHIFTING:
   • Works but O(n²) shifts
   • Example: [5a, 3, 5b, 2] → stable sort preserves 5a, 5b order

              11. MEMORY & CACHE PERFORMANCE
=================================================================================

11.1 CACHE ANALYSIS:
────────────────────

MEMORY ACCESS PATTERN:
• Outer loop: Sequential access (good)
• Inner loop: Random access to find minimum (bad)
• Swapping: Random access (bad)

CACHE MISS ANALYSIS FOR L1 CACHE (typically 32KB):
──────────────────────────────────────────────────
Assume: Cache line = 64 bytes, int = 4 bytes → 16 ints per cache line

For array size n:
• Best case (n fits in cache): Some reuse of cache lines
• Worst case (n >> cache size): Almost every access is a cache miss

CALCULATION FOR n = 10,000:
• Array size: 10,000 × 4 bytes = 40KB > typical L1 cache (32KB)
• Each inner loop iteration: Access random element → likely cache miss
• Total potential cache misses: ≈ n²/2 = 50 million (worst case)

11.3 OPTIMIZATIONS FOR CACHE:
─────────────────────────────

1. BLOCKING (TILING):
   • Process array in blocks that fit in cache
   • Find minimum within block, then compare block minima

2. PREFETCHING:
   • Use software prefetch hints for next elements
   • Example: __builtin_prefetch() in GCC

3. LOOP INTERCHANGE (not applicable):
   • Selection Sort loops cannot be interchanged
   • Inner loop depends on outer loop index

           12. ALTERNATIVE DATA STRUCTURES
=================================================================================

12.1 SELECTION SORT ON LINKED LIST:
────────────────────────────────────

IMPLEMENTATION CHALLENGES:
1. No random access → O(n) to find minimum each time
2. Swapping nodes requires updating multiple pointers
3. Total becomes O(n²) with higher constant factors

LINKED LIST IMPLEMENTATION:
────────────────────────────
Node* selectionSortLinkedList(Node* head) {
    if (!head || !head->next) return head;
    
    Node* current = head;
    while (current) {
        Node* minNode = current;
        Node* temp = current->next;
        
        // Find minimum node
        while (temp) {
            if (temp->data < minNode->data) {
                minNode = temp;
            }
            temp = temp->next;
        }
        
        // Swap data (simpler than swapping nodes)
        int tempData = current->data;
        current->data = minNode->data;
        minNode->data = tempData;
        
        current = current->next;
    }
    return head;
}

COMPLEXITY ANALYSIS FOR LINKED LIST:
• Comparisons: O(n²) (same as array)
• Swaps: O(n) but each swap is O(1) data swap (not node swap)
• If swapping nodes instead of data: O(n²) pointer updates

12.3 SELECTION SORT WITH OTHER DATA STRUCTURES:
────────────────────────────────────────────────

1. WITH STACKS (Highly inefficient - O(n³)):
   • Use 3 stacks to simulate array operations
   • Practical only for theoretical understanding

2. WITH QUEUES (Even worse - O(n³)):
   • Rotate queue to find minimum
   • Extract minimum and enqueue to sorted queue

3. WITH HEAP (Transforms to Heap Sort - O(n log n)):
   • Build min-heap: O(n)
   • Extract min n times: O(n log n)
   • This is essentially Heap Sort, not Selection Sort

=================================================================================
           14. COMMON MISTAKES & PITFALLS
=================================================================================

14.1 IMPLEMENTATION MISTAKES:
──────────────────────────────

1. OFF-BY-ONE ERRORS:
   • Outer loop: for (i = 0; i < n; i++)  // WRONG - last element already sorted
   • Correct: for (i = 0; i < n-1; i++)
   
   • Inner loop: for (j = i; j < n; j++)  // WRONG - compares element with itself
   • Correct: for (j = i+1; j < n; j++)

2. INCORRECT MIN INDEX INITIALIZATION:
   • minIdx = 0;  // WRONG - should start at i
   • Correct: minIdx = i;

3. UNNECESSARY SWAPS:
   • Always swapping even if minIdx == i
   • Add check: if (minIdx != i) then swap

4. FORGETTING TO UPDATE MIN INDEX:
   • Only comparing but not updating minIdx
   • Correct: if (arr[j] < arr[minIdx]) minIdx = j;

14.2 CONCEPTUAL MISTAKES:
──────────────────────────

1. THINKING IT'S ADAPTIVE:
   • "Selection Sort is faster for nearly sorted data" - FALSE
   • It always does same comparisons regardless of input order

2. THINKING IT'S STABLE:
   • "Selection Sort preserves order of equal elements" - FALSE (default version)
   • Long-distance swaps break stability

3. OVERESTIMATING SWAP COUNT:
   • "Selection Sort does O(n²) swaps" - FALSE
   • It does O(n) swaps (advantage over Bubble Sort)

4. UNDERESTIMATING COMPARISON COUNT:
   • "Selection Sort adapts comparison count" - FALSE
   • Always exactly n(n-1)/2 comparisons

14.3 PERFORMANCE MISCONCEPTIONS:
─────────────────────────────────

1. "Selection Sort is good for large datasets" - FALSE
   • O(n²) becomes impractical for n > 1000

2. "Selection Sort is cache-friendly" - FALSE
   • Random access pattern causes many cache misses

3. "Selection Sort is the simplest to implement" - DEBATABLE
   • Bubble Sort and Insertion Sort are equally simple

4. "Selection Sort is optimal for small n" - CONTEXT-DEPENDENT
   • For very small n (n < 10), often Insertion Sort is better
   • Depends on cost of comparisons vs swaps

=================================================================================
                              CONCLUSION
=================================================================================

Selection Sort, while simple and intuitive, serves primarily as:
1. A teaching tool for understanding sorting fundamentals
2. A component in hybrid algorithms for small partitions
3. A solution for memory-write-constrained environments

KEY TAKEAWAYS:
──────────────
• Always O(n²) comparisons, regardless of input
• O(n) swaps - advantage when swaps are expensive
• Non-adaptive and generally unstable
• Poor cache performance due to random access
• Best suited for small datasets or constrained environments

For practical applications with larger datasets, prefer:
• QuickSort for general-purpose in-memory sorting
• Merge Sort for stable sorting or external sorting
• Heap Sort for guaranteed O(n log n) worst-case
• Insertion Sort for small or nearly sorted data

Despite its limitations, understanding Selection Sort provides a solid
foundation for learning more advanced algorithms and appreciating the
trade-offs in algorithm design.
